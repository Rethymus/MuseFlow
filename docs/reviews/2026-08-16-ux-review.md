## 二、根因分析（软件工程学）

### SE-1（P0）刷新后数据反序列化崩溃 —— Hive Map 强转
Hive CE 的 `BinaryReader.readMap()` 永远返回 `Map<dynamic, dynamic>`。
以下读取路径使用 `json as Map<String, dynamic>` 直接强转：
- `lib/features/knowledge/infrastructure/character_card_repository.dart:45,57`（向导创建的角色卡刷新即不可读）
- `world_setting_repository.dart:47,59`、`foreshadowing_repository.dart:51,64`、`guardian_annotation_repository.dart:51,69`、`plot_node_repository.dart:51,69`（同模式潜在雷）
- `lib/core/infrastructure/hive_adapters.dart` 全部 12 个适配器（`fragments` 是唯一类型化箱子，`FragmentAdapter.read` 刷新即抛错 → 碎片"消失"）
- `onboarding_progress_repository.dart:32`（静默丢弃引导进度）

同会话写入正常的原因：非 lazy Box 直接缓存 `put()` 的原对象，不经历序列化往返；
刷新后才走解码路径。`chapter_repository.dart:46` 已用 `Map<String, dynamic>.from(...)`
防御，是项目内已被验证的正确"轮子"。测试从未覆盖"关闭→重开"，因此缺陷漏网。

### SE-2（P0）新用户首启不进引导 —— Web 跳过预开箱
`main.dart:119-121` 在 Web 上完全跳过启动期打开 settings box；
路由守卫 `Hive.box('settings')` 抛 `HiveError` 被 `catch (_)` 吞掉 → 不重定向，
先落 `/editor`；直到用户点文稿卡触发下一次路由评估（此时门禁已把箱子打开）
才被甩进 `/onboarding`，形成"先建稿、后引导"的断裂体验。

### SE-3（P1）写作统计从未接线
统计采集器 `WritingStatsCollector` 只被**未路由的死代码** `EditorPage` 接线；
实际路由使用的 `EditorWithSidebar` 完全没有引用 → 正文字数永不入账。

### SE-4（P1）自动保存不回写内存字数
`ChapterAutoSave._flush` 只写仓库，不刷新 `ChapterNotifier` 的章节列表 →
状态栏/侧栏字数在写作会话内恒为旧值。

### SE-5（P1）引导向导不产出文稿
向导只创建全局世界观/角色卡并置完成位，从不创建 Manuscript；
`insertOpeningText` 写入的 `editorProvider` 在引导期恒为 null。

### SE-6（P2）错误信息直通用户
`Bad state:` 前缀、`TypeError: minified:jN<...>` 等实现细节原样渲染；
配置类错误只给"重试"。违反"错误消息应说明原因并给出下一步"的工程实践。

### SE-7（P2）测试盲区
所有仓库测试都在同一打开的箱子上跑 CRUD，缺少重载往返测试（正是 SE-1 漏检原因）。

### SE-8（P2）桌面端仅长按菜单
文稿卡编辑/删除仅 long-press 可达（`_showContextMenu` 还是空实现，实际靠外层
GestureDetector），无悬停可见操作 —— 桌面平台约定（右键/悬停菜单）缺失。

## 三、人体工程学（人因工程）问题

- **HF-1 反馈即时性**：字数是写作者的核心反馈回路（日目标、节奏感），
  当前延迟到"重新进入"才更新，违反 1 秒内即时反馈定律（SE-4）。
- **HF-2 错误恢复路径**：`未配置 AI 模型 + 重试按钮` 是无效操作回路，
  应提供"去配置"这一可直接消除错误原因的动作。
- **HF-3 触达目标密度**：6 项底栏在 390px 上每项约 65px，低于 M3 导航项
  最小宽度，误触率上升。
- **HF-4 干扰与心流**：备份横幅不可关闭、全局常驻、移动端折两行，
  对"进入写作心流"的目标构成持续干扰；应允许暂停提醒（snooze）。
- **HF-5 认知负荷**：向导头部 3 个出口（上一步/跳过/关闭）+ 底部 2 个
  （上一步/下一步）= 同屏 5 个导航控件，其中"跳过"（跳一步）与"关闭"
  （结束全部）语义近似但结果不同。
- **HF-6 数字可读性**：`10240.0 MiB` 这类机器单位应按量级自适应为 KB/MB/GB。
- **HF-7 昼夜适应**：仅暗色主题。夜间护眼合适，日间高照度环境下暗底反差
  造成视觉疲劳；写作工具应提供 浅色/深色/跟随系统（HF 标配）。
- **HF-8 语言一致性**："Show menu"、"characters remaining" 等系统内置英文
  与全中文界面混杂，产生认知摩擦。

## 四、设计学问题

- **D-1 视觉层级**：单一 seed 主题无组件级定制，卡片/表单/图表表面色同质化，
  层级感弱。
- **D-2 卡片信息密度**：`childAspectRatio 0.75` 高瘦卡片 + 80px 纯色封面条，
  单卡信息密度低、封面缺乏"书"的隐喻质感。
- **D-3 可供性（affordance）**：卡片操作不可见（无 hover 指示），
  可供性缺失 → 可发现性差（诺曼）。
- **D-4 标题重复**：统计页 AppBar 与正文重复两级"写作统计"。
- **D-5 规范**：横幅自制 Row 布局（应遵循 banner 语义与间距规范）；
  底栏 6 项违反 M3 3–5 项。
- **D-6 空态表现力**：48px 图标 + 两行文字，缺乏视觉锚点与次级引导
  （如"从模板开始"）。
- **D-7 无障碍设计**：① 侧栏 6 个导航项不出现在语义树（读屏用户无法导航）；
  ② 文稿卡对外暴露为 `progressbar` 角色（读屏误读）；③ 正文编辑器无语义节点
  （super_editor 上游限制，记录备忘）。

## 五、开源轮子复用方案（优于自造）

| 问题 | 复用的轮子 | 说明 |
|------|-----------|------|
| 系统组件英文文案（HF-8） | **flutter_localizations**（Flutter SDK 自带） | 配置 `MaterialLocalizations` zh 委托后，"Show menu"→"显示菜单"、"characters remaining"→"还可输入 N 个字符"等全部自动汉化，零自写文案 |
| 主题系统升级 + 昼夜双主题（HF-7、D-1） | **flex_color_scheme**（pub.dev，久经维护） | 成对浅/深主题、表面色分级、组件级 sub-theme，替代手写 ThemeData；保留靛蓝品牌种子 |
| 底栏 3–5 项规范（HF-3） | **Material 3 Navigation Bar 指南** | 官方规范直接约束 IA 决策 |
| Hive Map 反序列化（SE-1） | 项目内已验证模式 `Map<String, dynamic>.from()` | chapter_repository 的防御式拷贝推广到全部读取路径 |
| 统计图表等 | fl_chart / graphview（已在用） | 不重复造轮子 ✓ |
